Validation Rules & Parameters Matrix

Target Blueprint Filter: content.json Parsing Engine

Parameter Name Data Type Status Definition & Operational Purpose
title String Required The explicit presentation name of the documentation page. It directly hydrates the primary workspace <h1> element header and breadcrumb nav trails.
content String Required A high-level text overview or summary block. This raw text string is placed right underneath your main title text as an opening paragraph section.
supportedViews Array Optional Explicitly controls which view mode selector buttons are rendered. Acceptable values within the array wrapper are: "console", "html", or "markdown".
defaultView String Optional Forcefully dictates which view interface is chosen by default during the initial folder mount. This overrides the automatic state engine logic waterfall checklist loop (html ➔ markdown ➔ console).
allowCopy Boolean Optional Enables or disables visibility for the copy action control icon button on the terminal sub-header layout strip. Defaults internally to true if left completely undefined.
💡
Architecture Review Commentary: Every single subdirectory located within the /dev-docs/ pipeline framework requires a valid content.json file to serve as its validation checkpoint entry card. If this file is missing, the compile-time data compiler will treat the directory as unassigned space and drop it completely from the dynamic sidebar rendering loop.

The Sidebar Stack Order is derived from the folder names:

├── dev-docs                           <-- Document Root Folder
│   ├── 00-documentation-engine        <-- Document Sidebar Section Header
│   │   ├── 01-intro                   <-- Document Sidebar Section Card
│   │   │   ├── blueprint.md
│   │   │   ├── content-rules.html
│   │   │   ├── content.json
│   │   │   ├── setup.sh
│   │   │   └── workflow.md

The default syntax is XX_Name where XX equals a two-digit integer.
If XX is missing, the order is derived alphabetically.
